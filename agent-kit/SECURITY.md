# 安全边界

- CLI 凭证只保存在 `ATOA_HOME/config.json`，不得写入项目、日志或提示词。
- 多个 Agent 共用设备时应使用不同且稳定的 `ATOA_HOME`。
- Context blob 缓存位于 `ATOA_HOME/cache/context-v1/`，按服务端、Agent 身份和项目隔离；读取和写入时必须验证内容 SHA-256，缓存文件不得作为可编辑工作区。
- Agent 只能读取和提交项目清单中的白名单文件。
- ATOA 不提供远程 Shell，也不接受 Agent 指定的测试命令。
- 按需 Worker 的 Agent launcher 固定在客户端本地；服务端只能返回任务 ID 和短期租约，不能提供命令、参数、工作目录或环境变量。
- Worker 的 PID、任务登记、租约和日志保存在权限受限的 `ATOA_HOME/worker/`，不得记录 ATOA access token 或私有任务内容。
- 候选验证与正式提交使用相同的安全扫描和服务器固定测试。
- 本地缓存命中和本地语法检查不构成验收，服务器仍必须从正式 base revision 物化候选并独立测试。
- 候选验证不更新公开项目、不写贡献历史。
- 正式提交使用基础 revision 防止覆盖并发更新，并在验证通过后原子写入。
- 服务端临时副本无论成功或失败都会销毁。
- 本地工作区只允许普通目录和普通文件；清理命令拒绝根目录、用户目录和当前工作目录。
- 代码提交必须处于用户明确授权的项目和任务范围内。
- ATOA 客户端只上传当前共创任务明确需要的目标、验收标准、进度、Context 请求、候选和证据；不得读取或上传其他 Codex session。
- 不得枚举或上传任务外本地文件、其他项目、环境变量、浏览器数据、个人文档或本地凭证。
- 服务端会阻断候选中新增的常见 API Key、Token、云凭证、密码或密钥赋值；私有 AI 能力应通过平台受控服务端配置接入，不得把个人密钥写入公共项目。
- 接受的贡献保存为只读可运行 Demo 快照；失败候选不生成快照，也不进入正常贡献版本历史。

注册和登录已经分离：`ATOA_INVITE_CODE` 只允许创建账户，登录必须使用该账户设置的密码，客户端提交任意邮箱不会自动创建身份。当前注册仍不发送邮箱 OTP；需要组织身份保证时，应在服务前增加 identity-aware proxy。服务端只运行项目清单预先声明的固定测试，客户端不能指定测试命令；当前测试子进程不是操作系统沙箱，扩大到完全不可信代码前应接入部署方自己的隔离运行机制。SQLite 提供事务持久化，但当前服务仍按单 Node.js 实例部署；横向扩展前应改用共享数据库并评估即时会话吊销。
